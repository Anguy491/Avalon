## 实现证据

- 游戏裁决继续只存在于 `packages/game-engine`；M4 没有在移动端复制人数表、计票、阈值或胜负算法。
- `ProposalRecord` 公开投影增加服务端权威 `approveCount/rejectCount`；`PublicSnapshot.requiredQuestFails` 让客户端在提交前显示双失败规则而无需重算。
- `availableActions` 按玩家、阶段和阶段门生成：队长组队、未提交玩家投票、获批队员任务行动；善方只收到 `SUCCESS`。
- 移动端使用单一 `/game` 路由，私密选择仅在组件内存；后台、阶段变化和成功提交会清空草稿，任务选择提交后卸载并进入中性等待。
- 结算前投影只含总进度；组队票在全员到齐后一起公开；任务历史只含队伍、匿名成功/失败数量和阈值，不含行动归属。
- 三次成功进入不揭示角色的刺杀等待，三次失败或五拒显示锁定胜因摘要；完整刺杀、角色揭示与终局确认留给 M5。

## 原生验收与边界

- `pnpm test:e2e:mobile` 已尝试执行，但本机缺少 Java Runtime，Maestro 在启动前退出；现有 Maestro 套件只覆盖 M2 创建/加入/拒权，即使环境补齐也不足以证明 M4 私密操作。M4 仍需补充多客户端驱动并在 iOS、Android 各运行一次真实投票与任务提交，保存正常、错误、最大字体和读屏证据。
- 当前实现不增加音频播放、10 秒断线暂停或多暂停原因，这些属于 M6；不增加刺杀控件、完整结果页或终局收据，这些属于 M5。
- 测试使用合成昵称、本地临时房间与一次性 token；日志和文档不记录 token、角色分配或任务行动映射。
