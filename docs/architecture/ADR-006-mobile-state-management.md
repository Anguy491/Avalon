# ADR-006：服务端投影进入 TanStack Query，Zustand 仅管理临时 UI

- 状态：已接受
- 日期：2026-08-13

## 背景

客户端同时包含 HTTP 恢复数据、Socket.IO 推送、表单草稿、弹层状态、音频设置和安全会话。若将它们混入一个全局 store，容易把过期公开状态、本地推断和秘密动作草稿误当作权威状态。

## 决策

- TanStack Query 保存按当前会话键控的最新 `RoomView` 和请求生命周期；
- Socket.IO 收到合法新版本后通过单一适配器更新同一 Query cache；
- Zustand 只管理不可裁决的瞬时 UI：当前弹层、非秘密选择焦点、教程状态、连接提示和房主本地音量；
- React Hook Form 管理昵称、房间配置等表单；Schema 提供边界校验，服务端仍是最终校验者；
- `SessionToken` 只存 Expo SecureStore，不进入 Query、Zustand、AsyncStorage、URL、错误对象或遥测；
- 本人的角色投影只保存在内存 `RoomView`；应用后台使用隐私遮罩，房间关闭/过期/令牌失效时主动清空；
- 投票、任务行动和刺杀目标在二次确认前仅保存在当前组件内存，确认后立即清除，不进行离线队列或持久化；
- Zustand store 不得导入 `game-engine` 或实现规则推导。

## 版本处理

- 新投影版本 `>` 本地版本：原子替换；
- `=`：忽略状态替换，仍按 `audioCueId` 去重；
- `<`：丢弃并记录无秘密诊断指标；
- 版本缺口：可以先显示新完整投影，同时触发一次后台读取校验；若 Schema/会话异常则进入阻塞恢复页。

## 结果

远端状态只有一个缓存位置，HTTP 与实时来源能收敛；秘密动作不会因网络恢复自动重放；UI 状态保持轻量。

代价是需要编写明确的 Socket.IO→Query 适配器和清理逻辑，开发者不能随意把服务器字段复制到 Zustand。

## 未采用方案

- Redux Toolkit：能够胜任但对当前规模增加样板，且仍需另行处理请求缓存；
- 全部使用 Zustand：缺少标准请求失效、恢复和重试语义；
- 全部使用组件状态：跨路由恢复和实时推送难以一致；
- 客户端事件溯源：与完整投影协议和服务端权威原则冲突。

## 验证

- 断线、回前台和 token 轮换后只有一个当前 `RoomView`；
- 清理会话后内存、SecureStore 和持久化偏好均无角色/令牌残留；
- 未确认动作在页面销毁/断网后不会自动提交；
- 状态 store 静态依赖检查不引用游戏引擎。
