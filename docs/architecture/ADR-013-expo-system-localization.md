# ADR-013：Expo 系统语言本地化，微信小程序保持中文

- 状态：已接受
- 日期：2026-08-22

## 背景

iOS/Android Expo 应用需要提供简体中文与英文界面，同时保持同一房间内的服务端裁决、协议字段和中文主持语音一致。微信小程序已有独立中文 UI，本次不应为其引入语言切换或扩大共享状态边界。系统语言也可能在应用后台期间变化，iOS 还允许用户为单个 App 选择语言。

把中文展示文案写入派生状态或成功提示会导致运行中切换语言后保留旧语言，并可能诱使客户端以文案参与分支。音频资源则已有获批的 `zh-CN-v1` 清单，不应为了英文界面修改生成文件或协议。

## 决策

- Expo 使用 `expo-localization` 读取系统语言偏好，按顺序选择第一个 `zh-*` 或 `en-*`；中文变体统一映射为 `zh-CN`，无匹配项时回退 `en`；
- 应用启动及每次回到前台时重新解析语言，不提供应用内开关，不持久化语言，不重建当前会话；iOS 声明中英文以支持系统单 App 语言；RTL 关闭；
- 使用 `i18n-js` 和类型安全的中英文 catalog 处理插值与单复数。页面、无障碍文案、服务端 `ErrorCode`、角色/阵营/阶段/胜因和成功提示均从稳定语义键在渲染时翻译；
- `@avalon/client-core` 提供昵称校验语义错误码；现有中文 `nicknameError()` 保留给微信小程序兼容使用；
- 英文界面继续播放 `zh-CN-v1` 中文主持音频，并按完整 `VoicePackKey` 映射显示英文字幕。中文字幕继续逐项匹配获批生成清单，不手工修改生成语音包文件；
- 应用名称“曼波阿瓦隆”保持不变；iOS 相机权限说明提供中英文原生资源；
- 微信小程序、服务端、协议 Schema、`RoomConfigInput.locale: "zh-CN"` 和语音包版本不变。

## 结果与权衡

界面语言可以在回前台时即时更新，当前提示也会重新翻译，同时不会影响房间状态或秘密投影。所有中文变体使用简体中文，避免在没有审核繁体文案时产生不完整体验。无匹配语言回退英文符合面向新增英文用户的默认行为。

代价是每个新增移动端语义值和可见状态必须同时补齐两份 catalog，并通过完整映射测试。原生语言与权限元数据变化需要重新生成或安装原生构建；仅刷新 JavaScript bundle 不能验证系统单 App 语言入口。

## 验证

- 单元测试语言偏好顺序、中文/英文变体、英文回退、catalog 键一致性以及全部错误码、角色、知识标签、阶段、胜因和音频键映射；
- iOS/Android Maestro 分别运行 `zh_CN` 和 `en_US` 核心流程，英文覆盖正常、错误与相机拒绝状态；
- 人工验证系统/单 App 语言切换后回前台立即更新、会话不丢失，并检查英文最大字体与无障碍标签；
- `audio:verify` 证明获批中文音频未漂移，微信小程序构建与中文回归证明平台边界不变。
