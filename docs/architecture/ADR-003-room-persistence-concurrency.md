# ADR-003：PostgreSQL 聚合快照、房间行锁与事务 Outbox

- 状态：已接受
- 日期：2026-08-13

## 背景

相同房间可能从多个应用实例同时收到最后一票、重试命令、连接变化或过期任务。`stateVersion` 能发现客户端过期，但不能独自防止两个服务器并发提交。服务还必须在进程崩溃后保持已确认命令 RPO 0。

## 决策

### 权威存储

PostgreSQL 保存：

- 每个房间一条当前聚合快照与 `state_version`；
- 玩家与会话摘要，其中 SessionToken 只保存加盐密码学哈希；
- `processed_commands` 的命令 ID、请求摘要和原始响应；
- 事务 Outbox；
- 公开可审计历史。任务行动的玩家映射只存在于结算事务内，提交后销毁。

### 命令事务

每个改变房间的命令执行：

1. `BEGIN`；
2. 按 `room_id` 执行 `SELECT ... FOR UPDATE`；
3. 验证会话、幂等记录和 `expectedStateVersion`；
4. 调用纯游戏引擎并断言不变量；
5. 更新快照、幂等响应并写 Outbox；
6. `COMMIT` 后才向客户端确认。

单事务只锁一个房间；不得在持锁时进行网络调用、音频读取或等待用户。数据库死锁/序列化失败只允许有限次数、带抖动的服务器内部重试。

### 广播与临时状态

Outbox worker 构建每名玩家的完整投影并发布；重复发布可由 `eventId/stateVersion` 去重。Redis 只承担跨实例 Socket.IO adapter、限流计数和短期连接租约，不保存唯一权威聚合。连接超时转换和房间过期最终都写回 PostgreSQL。

### 生命周期

活跃/暂停房间按 `NFR-006` 恢复。进入 `GAME_OVER` 后，Outbox 只负责向当前全部在线会话投递一次终局个性化投影；全部会话确认或 60 秒超时后，删除房间聚合、玩家会话、processed commands 和 Outbox。客户端结果只存在于内存，终局后不提供历史或恢复。

暂态房间表不得进入长期备份；复制、WAL 和托管供应商日志的物理残余时限必须在邀请测试前形成运维决策并向所有者披露。角色与私密知识存为受限秘密 blob，使用云 KMS 管理的应用层信封加密或等效控制。无 roomId/playerId/nickname 维度的聚合运营指标不属于对局历史。

## 结果

同房间命令获得明确串行顺序，跨房间仍可并行；状态更新和待广播记录原子提交；不依赖单个 Node 进程恢复。

代价是热门房间存在单行串行瓶颈，但每房最多 10 人且命令频率低，符合领域天然顺序。JSON 聚合的查询能力有限，运营分析必须使用无秘密派生指标。

## 未采用方案

- 完整事件溯源：MVP 重放、迁移和秘密事件治理复杂度过高；
- Redis 作为权威状态：持久性与事务/备份语义不足；
- 仅靠 `stateVersion` 的无锁更新：幂等记录、自动裁决和 Outbox 难以作为一个清晰事务维护；
- 数据库事务跨玩家讨论期：不可接受，所有等待发生在事务外。

## 验证

- 两个实例并发提交同一版本时至多一个成功；
- 在提交前、提交后确认前、Outbox 发布前后注入崩溃，最终状态无重复裁决；
- Redis 清空或实例重启不会丢失权威房间；
- 终局确认/60 秒超时测试证明房间、会话、去重和 Outbox 被清除，且不存在历史读取接口。
